## Architecture and availability

The request-time loader consumes the existing selected E brief, its exact D
snapshot bytes, current A/B/C bytes and optional associated F/G context. It uses
the existing A/B/C/D/E validators and rejects a snapshot that does not agree with
the selected current run and all four current bindings. It checks the selected
proof, displayed brief, exact snapshot digest and input identities again during
loading. It never substitutes current evidence into a historical snapshot.

The source metadata parse follows source/proof validation. The examined count
comes from source records whose IDs occur in validated examination coverage;
it must equal the recorded examined count. Candidate wording, human disposition,
human-review scope and frozen dissent are copied without semantic rewriting.

Optional F records are reread, fingerprint checked and validated using the
existing F validator. Association requires the exact run, candidate, snapshot
name/hash, canonical E projection hash and all frozen input bindings. The loader
uses an associated saved F record displayed below, preferring the selected G
decision when available. It does not attach another snapshot's decision. G is
reconstructed with its existing validator against that same F and independently
read current comparison inputs. Its comparison run is visible.

Presentation states describe rendering availability only:

- `READY`: valid current selected core, associated validated F/G context and
  complete theme metadata support this presentation.
- `PARTIAL`: valid core remains visible when optional F/G context is unavailable,
  invalid or not associated, or theme metadata is incomplete. Missing optional
  context is not presented as proof that no decision or comparison exists.
- `BLOCKED`: required selected evidence cannot validate together or is historical
  relative to the selected current evidence. No interpretation or zero-finding
  state is fabricated. Earlier detailed sections retain their own validation and
  historical-access behavior, including G's frozen decision inspection.

The projection exposes no recommendation, trust, confidence, readiness, consensus
or decision-correctness field. Deterministic reconstruction rejects extra or
altered projection fields; it does not confer new evidence authority.

## WITNESS boundary, limitations and review gates

> Verification must name its boundary.
>
> Summary is not the product. The evidence trail is.

H mechanically verifies identities, existing artifact structures/bindings and
deterministic presentation. It does not prove semantic correctness, materiality,
truth, consensus, representativeness, participant-confirmed meaning, complete
dissent detection, policy sufficiency, decision correctness or organisational
effectiveness. Model interpretation remains model interpretation. HUMAN-REVIEWED
means only the preserved saved review. A recorded human decision does not settle
unresolved evidence. Synthetic tests do not establish performance on real citizen
testimony. Theme frequency does not establish importance.

Portable historical validity and current local agreement are separate. H's
current-only orientation may be blocked while the historical E/F/G evidence is
still valid and inspectable below. G is a page-load comparison, not a live monitor.
Repeated reads narrow but cannot eliminate filesystem races. Existing hashes and
validators are not signatures and do not authenticate identities, authorship,
authority, timestamps or a coherently rewritten bundle against an external trust
anchor. H adds no such authority.

Human demo-comprehension acceptance is outstanding after SMITH mechanical review.
Without scrolling into the detailed proof, the human steward must be able to say:

1. What is this consultation evidence?
2. What does the current system interpretation say?
3. What disagreement/uncertainty remains?

First-viewport comprehension at actual display sizes has not been accepted.
Keyboard/focus, mobile width, 200% zoom, reduced motion and forced colours require
separate browser/release review. Unit/component/HTTP checks do not substitute for
these gates. No browser automation harness was added.
